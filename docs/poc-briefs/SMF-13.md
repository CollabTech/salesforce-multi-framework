## Question this probe answers
Can a technician inspect a simple 3D equipment model (load, orbit, zoom, select a part, reset,
resize/rotate, touch) inside the Salesforce hosts, fast enough to use, and does it fail safely?

## Bounded scope
In: one probe route `probes/3d` (`uiBundles/FieldSupport/src/probes/smf-13-3d/`) loading the
bundled MF-MODEL-SMALL; timing marks; scripted 60 s camera path with frame sampler; WebGL check;
context loss/restore; dispose with renderer.info before/after; static-image fallback with alt text.
Out: Files delivery, MF-MODEL-REP, budgets (SMF-14); collaboration on the model.

## Design
- **Library:** three.js **0.186.1** (exact pin; `@types/three` 0.186.0), GLTFLoader + OrbitControls
  (touch: one finger rotate, two finger dolly/pan). Plain three.js, not React Three Fiber, to keep
  one dependency. Lazy-loaded route chunk (~667 kB min / 171 kB gzip) so the launch app stays light.
- **Fixtures (owned here per SMF-3):** `testing/fixtures/models/generate-models.mjs` builds a pump
  (base, volute casing, inlet, outlet, impeller, bearing housing, coupling, finned motor,
  terminal box, bolts — named nodes with `partId`/`label` extras) deterministically; CC0-1.0,
  generated by this repository, no third-party assets; validated with Khronos glTF-Validator
  (0 errors). `manifest.json` records bytes, sha256, triangles, meshes, textures, generator
  command and Node version. MF-MODEL-SMALL: 317,796 B, 8,676 triangles, 10 meshes, 0 textures.
  Missing-asset control: `MF-MODEL-MISSING.glb` (must not exist). Fallback:
  `MF-MODEL-FALLBACK.png` (960×640, software-rasterised from the model geometry, no metadata).
- **Load timing:** request start → bytes → parsed → first frame → interactive (next frame).
- **3D-02 protocol:** time-based camera path (orbit, zoom, elevation sweep, one part selected per
  second), user input disabled, every frame interval sampled; median/p5/p95 fps, long frames
  (> 50 ms). Targets fixed in code (`TARGETS`): usable ≤ 10 s and median ≥ 30 fps.
- **Failure handling:** missing model (404 or an SPA HTML page) → "invalid/missing" → static
  image + parts list; `webglcontextlost` → static image until `webglcontextrestored`;
  WebGL unavailable (real or simulated) → static image; unmount disposes geometries,
  materials, textures, ImageBitmaps, render lists, renderer and forces context release.

## Limitations
- Localhost runs use SwiftShader software WebGL in headless Chromium 141: functional evidence
  of probe logic only; fps/load figures are not device evidence.
- `renderer.info.memory.textures` stays at 1 after model disposal: three.js's shared DFG
  lookup table (PBR), not a model texture; released with the renderer/context.
- Embedded textures (SMF-14 REP) decode through in-page `blob:` URLs; host CSP must allow them
  (unverified in Salesforce until a host run).
