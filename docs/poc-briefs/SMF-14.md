## Question this probe answers
What scene budget keeps equipment models usable on field devices, and is the model (with its
textures) delivered only to users who may see the case?

## Bounded scope
In: probe `probes/3d-budget` (`src/probes/smf-14-budget/`), delivery of MF-MODEL-SMALL/REP as
case-linked Salesforce Files in user context, denial controls, a harness (5 open/close + the
SMF-13 60 s protocol per model, JSON output), orientation/foreground monitoring, budget
derivation and fallback rule. Out: new Apex (SMF-10's read API is reused), model authoring
tools, compression formats (Draco/KTX2) — untested, so not claimed.

## Design
- **Fixtures:** generated by SMF-13's `testing/fixtures/models/generate-models.mjs` (CC0-1.0).
  REP = 8,647,528 B, 240,692 triangles, 141,722 vertices, 10 meshes, 4 embedded PNG textures
  (cast-normal 1024², casing-paint 1024², casing-metal-rough 512², motor-paint 1024²).
  glTF-Validator: 0 errors, 6 warnings (generated tangent space; unused UVs on untextured parts).
- **Delivery (user context; access follows Files sharing):** (a) SMF-10 Apex REST
  `/services/apexrest/smf10/v1/versions/{versionId}/data` via the SMF-10 transport (with sharing
  + USER_MODE) and (b) Connect REST `/connect/files/{documentId}/content` via `sdk.fetch`.
  `sobjects/.../VersionData` is not used (not on the skill's allowlist) — see
  `docs/contradictions.md` C-SMF14-01, incl. the 6 MB Apex heap ceiling on path (a).
- **Textures** are embedded in the GLB BIN chunk; the probe rejects any GLB with an external
  URI and the loader's URL modifier refuses any non-`blob:`/`data:` request (recorded). The
  bundled MF-MODEL-SMALL app asset (SMF-13) is the one path not checked against case sharing and
  is reported as such.
- **Model Files provisioning:** stage `47-smf14-model-files.sh` (MF-ADMIN, setup only) uploads
  SMALL/REP linked to MF-CASE-001 and `*-DENIED` copies linked only to MF-CASE-002 (ShareType V,
  AllUsers, no public link), idempotent by Title + MD5; Ids to `private/`.
- **Budget (BUDGET-04):** `budget.ts` names, per device, the largest fixture that met every
  target on that device; software renderers and non-required rows are excluded; nothing is
  extrapolated. Proposed fallback trigger in `FALLBACK_TRIGGER_RULE`.
